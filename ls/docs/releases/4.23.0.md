# LocalSetup 4.23.0

LocalSetup now prepares and checks release documentation before the publication workflow builds a release archive. A structured release record keeps homepage highlights, entry-page links, the release guide, and GitHub notes aligned with the planned version.

## Highlights

- **Release-aware documentation:** Canonical version planning drives one checked content record and the managed current-release sections. Stale versions, rendered-content drift, broken guide links, and incorrect verification archive names block preparation.
- **Source-backed authoring and review:** Active public documents receive static checks, with targeted editorial review against committed changes. The protected, tool-free QC runtime proposes edits and independently reviews them with bounded calls, deadlines, source receipts, and public-link preservation.
- **Documentation-only repair:** The repair workflow can update published release prose without rebuilding packages or replacing tags and assets. It refuses to describe unreleased executable changes as part of an already published release.
- **Preserved release history:** Version synchronization leaves historical release guides intact while refreshing the current version and generated documentation.

See the [published release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.23.0) for release assets.

## Compatibility

The framework command and Python distribution remain `localsetup`. Existing adapter ownership, recorded selections, and ordinary installation/update behavior are unchanged.

Automated release preparation requires the existing QC endpoint, credential, model configuration, and a successfully provisioned protected runtime. Missing configuration, incomplete review, or failed validation stops the release path.

The workflow continues into the existing draft and artifact handoff. Complete native artifact assembly and final public release publication are not automated by this change. Dependency versions and native runtime code are unchanged.

## Update

Follow the quickstart update instructions to refresh the registered source to the intended release. `localsetup update` reapplies that source; it does not download a newer framework release. Explicit source checkouts remain under the user's control.

Once the registered source is current, preview the target:

```bash
localsetup plan --target-directory .
```

Review selections and clear blockers before applying:

```bash
localsetup update --target-directory .
localsetup verify --level filesystem
```

Repository maintainers should run the publish workflow's `qualify` mode before enabling the release path. Qualification integrates and validates only on its ephemeral runner, without pushing or creating a release. The versioning guide documents `release` and `repair` modes.

For installation and source refresh, read the [quickstart update instructions](../QUICKSTART.md#update). Adapter changes follow the [adapter ownership guide](../ADAPTER_OWNERSHIP.md).

## Verify the download

When this release is published, download `localsetup-v4.23.0.tar.gz`, `localsetup-v4.23.0.tar.gz.sha256`, and `localsetup-v4.23.0.tar.gz.cdx.json` together and keep all three files in the same directory.

Use `verify-release` to check the archive and its checksum and SBOM sidecars. Before publishing a draft, maintainers must also verify the complete wheel, source-distribution, and required native artifact inventory, then run the release-documentation draft check against the exact release commit.

Download the framework archive with both its `.sha256` checksum and `.cdx.json` SBOM sidecars. Keep all three files in the same directory before running `verify-release`.

```bash
uv run --locked python ls/tools/localsetup.py --source-root . verify-release /path/to/localsetup-v4.23.0.tar.gz
```
