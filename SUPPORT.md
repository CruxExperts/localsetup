# Support

Localsetup support happens through GitHub so project context stays visible and searchable.

## Bugs

Use the bug report issue form. Include the Localsetup version, platform ID, command, expected result, actual result, environment, and the shortest useful validation output.

## Maintenance and Release Problems

Use the maintenance issue form for version-sync failures, generated-doc drift, publish workflow failures, public package artifact problems, branch/ruleset questions, or label/project automation.

## Feature Requests

Use the feature request issue form. Name the affected platform, skill, workflow package, pack, docs page, or template, and describe the compatibility impact.

## Questions

Use GitHub Discussions for usage questions, early ideas, and design conversation that is not yet an actionable bug or feature request.

## Security

Do not post vulnerability details, exploit steps, secrets, private hostnames, private paths, or sensitive logs in public issues. Use GitHub private vulnerability reporting when available, or use the security contact request form without technical details.
